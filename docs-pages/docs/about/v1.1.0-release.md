## po 命令：42 个子命令，7 大模块

`po` 的完整命令树长这样：

```text
po
├── pdf       (11)  转换、合并、拆分、加解密、水印
├── excel     (7)   模拟数据、合并拆分、查数据、转 PDF
├── file      (8)   批量重命名、搜索、按名分组
├── image     (8)   压缩、水印、词云、二维码、铅笔画
├── tools     (6)   翻译、域名转 IP、密码、生成文章
├── markdown  (1)   Excel 转 Markdown
└── finance   (1)   股票 T+0 收益计算
```

一共 **7 个模块、42 个子命令、121 个参数**。

### 三个最实用的场景

**场景一：合并 PDF（最常用的一个）**

```bash
po pdf merge2pdf 报告A.pdf 报告B.pdf --output-file 合并报告.pdf
```

**场景二：Excel 转 PDF**

```bash
po excel excel2pdf 报表.xlsx 报表.pdf
```

**场景三：查一个域名解析到哪个 IP**

```bash
po tools url2ip www.python-office.com
```

### 命令结构是「模块 + 子命令」两级

这一点和大多数 CLI 工具一致，习惯之后很好记：

```text
po <模块> <子命令> [位置参数] [--选项]
```

每个子命令都自带 `--help`，可以逐个查：

```bash
po --help                  # 列出全部 7 个模块
po pdf --help              # 列出 pdf 模块的 11 个子命令
po pdf merge2pdf --help    # 查看某个子命令的全部参数
```

### 参数怎么写：kebab-case 长选项

Python 函数的参数是下划线风格（`input_file`），命令行里统一转成中划线风格（`--input-file`），这是 CLI 的通行做法：

```bash
po file replace4filename ./目录 "旧文本" --file-rename true --suffix .txt
```

布尔参数接受 `true/false/1/0/yes/no/on/off` 多种写法，不用背。

### 平台守卫：为 Windows 专属功能预留的拦截机制

python-office 有一部分能力依赖 Windows 上的 Office（比如 Word 转 PDF、PPT 处理）。分发层的设计是**先做平台守卫，再导入模块**——不在目标平台上的模块会在导入之前就被拦下来，给出明确提示，而不是让你在堆栈里翻半天。

本波注册的 7 个模块全部是跨平台的，所以目前还没有模块会触发这个守卫。守卫机制本身有测试覆盖：通过注入一个 Windows 专属模块来验证拦截行为——报错信息形如

```text
po: error: module 'xxx' is only available on: win32 (current: darwin)
```

同时，**尚未纳入本波的模块（word / ppt / video / web / wechat 等）目前是直接不存在的**：

```bash
po ppt ppt2pdf
# po: error: argument <module>: invalid choice: 'ppt' (choose from excel, file, finance, image, markdown, pdf, tools)
```

第二波补齐这些模块时，Windows 专属的部分就会走守卫逻辑——**先守卫后导入，跨平台调用不会触发任何 import**。

### 设计细节：注册表驱动，加命令不用改架构

CLI 的核心是一个**声明式注册表**（`office/cli/commands.py`），每个命令自己声明参数信息：

```python
"pdf2docx": {
    "help": "Convert PDF to docx",
    "params": [
        {"name": "input_file", "positional": True, "metavar": "PDF",
         "help": "input PDF file"},
        {"name": "output_file", "help": "output docx file"},
    ],
},
```

这个结构带来两个直接好处：

- **`po --help` 零依赖**。构建解析器时不需要 import 任何 `office.api` 模块，所以即使你只装了 `popdf`，`po --help` 也秒开，不会因为缺 `povideo` 之类的重依赖而报错。
- **加新命令只是加数据条目**。不用改分发逻辑、不用改参数解析逻辑。

分发时还有一层保护：用 `inspect.signature` 过滤参数，注册表里多写的参数不会传进 API 函数，避免 `TypeError`。

## 为什么 `--json` 比命令本身更重要

这是 1.1.0 最容易被低估、但实际价值最大的一个设计。

```bash
po --json tools url2ip www.python-office.com
```

输出**只有一行 JSON**，stdout 干净到可以直接被脚本解析：

```json
{"ok": true, "result": "1.2.3.4"}
```

出错时同样是一行 JSON，退出码为 1：

```json
{"ok": false, "error": "FileNotFoundError: [Errno 2] No such file or directory: 'a.pdf'"}
```

### 一个容易被忽略的细节

python-office 内部的库函数会自己 `print`（比如进度条）。如果不做处理，stdout 里就会混入一堆进度信息，脚本解析直接崩。

`po` 的处理方式是把**库内部输出全部重定向到 stderr**，保证 stdout 只有那一行 JSON：

```text
stdout:  {"ok": true, "result": null}      ← 只有这一行
stderr:  rows: 100%|██████████| 5/5 ...    ← 进度条在这里
```

这个边界很多人会漏，但它是「CLI 能不能被脚本可靠调用」的分水岭。

### 为什么这对 AI Agent 特别重要

现在的 AI Agent（Claude Code、Cursor、Codex 等）执行命令时，最怕的就是**输出不结构化**——要么解析失败，要么把进度条噪音当成结果。

`po --json` 天然适合做 Agent 的工具调用：

| 需求 | `po --json` 的表现 |
|---|---|
| 判断成功还是失败 | 看 `ok` 字段，不用解析错误文本 |
| 拿到结果 | 看 `result` 字段 |
| 拿到错误原因 | 看 `error` 字段 |
| 判断要不要继续 | 看退出码（成功 0 / 失败 1） |

所以如果你在搭 Agent 工作流，**python-office 的 81 个 Skill 现在有了统一的命令行调用入口**。

### 兼容的 Python 调用方式

CLI 的设计对现有代码零侵入。原有写法全部照常可用：

```python
import office
office.pdf.pdf2docx()          # 照旧
from office import pdf         # 照旧
from office import *           # 照旧
```

## 导入变快了：PEP 562 懒加载

这是 1.1.0 里最容易被忽略、但对用户体验影响最大的改动。

### 改之前

```python
import office
```

这一行会把**全部 14 个 API 模块**的依赖树一起拖进来——`poexcel`、`popdf`、`povideo`、`poocr`、`pospider` 全都加载。哪怕你只想处理 PDF，也得装齐一整套。

### 改之后

Python ≥ 3.7 走 PEP 562 模块级 `__getattr__`，改成**按需加载**：

```python
import office          # 此时不加载任何 po* 子库
office.pdf             # 访问属性时，才 import office.api.pdf → popdf
```

实测行为（Python 3.12）：

```text
import office 之后加载的 po* 模块：[]          ← 空
访问 office.pdf 之后：popdf, pofile, ...       ← 按需加载
```

### 实际收益

| 收益 | 说明 |
|---|---|
| **安装体积** | 只用 PDF 的用户不必装 povideo / poocr / pospider 这些重包 |
| **启动速度** | `import office` 不再是「等半天」 |
| **Docker 镜像** | 核心 CLI 镜像只装 8 个子库即可，全量依赖里 moviepy、paddleocr 这类装一次就好几分钟 |
| **兼容性** | Python 3.6 无 PEP 562，自动回退到原来的 eager 导入，行为不变 |

### 一个待观察的取舍

`office/__init__.py` 里不再有真实的 `from office.api import ...` 语句了，**IDE 的「跳转定义」和自动补全会退化**。如果你的编辑器里 `office.pdf` 跳不到定义、也没有补全提示，这是 1.1.0 引入的已知副作用。

维护者在合入时保留了这个方案，但明确记了账：后续如果社区反馈跳转体验下降，可以考虑把懒加载下沉到 `office/cli/` 内部，`office/__init__.py` 保持原样。**如果你重度依赖 IDE 跳转，升级后请先验证一下。**

## 新增 5 个 Excel 数据核对方法

除了 CLI，贡献者还补齐了「表格处理」链条里缺的一环。现有方法主要解决**格式转换与合并**，这次补上的是**比对、去重、质量统计**。

### 方法一览

| 方法 | 作用 | 与既有方法的区别 |
|---|---|---|
| `excel_diff` | 比对两份 Excel，输出单元格级差异 | `merge2excel` 是合并，本方法是找差异 |
| `excel_dedupe` | 按列或整行去重 | 既有方法没有重复检测能力 |
| `excel_column_stats` | 逐列画像：填充率、类型、唯一值数、数值分布 | `find_excel_data` 按关键词找内容，本方法按列做画像 |
| `excel2json` | 工作表转 JSON，三种结构可选 | `excel2markdown` 输出给人看，本方法输出给程序读 |
| `excel2csv` | 导出 CSV，支持多表批量 | `excel2pdf` 输出 PDF，本方法输出纯文本 |

全部只依赖 `openpyxl`（已在项目依赖链里），Python 3.6+ 兼容，**没有引入任何新的第三方包**。

### excel_diff：主键配对，避免「一行插入全表标红」

这是 5 个方法里设计最讲究的一个。

```python
from skills.excel import excel_diff

result = excel_diff(
    before_path='上周报表.xlsx',
    after_path='本周报表.xlsx',
    key_column='订单号',
    output_path='差异.xlsx',
)

print(result['summary'])
for item in result['changes']:
    print(item['key'], item['column'], item['before'], '->', item['after'])
```

两种比对模式：

- **按位置比对**（默认）：逐单元格比较，适合行顺序固定的表。
- **按主键比对**（指定 `key_column`）：先按主键配对行，再比较同一主键下的字段。

为什么必须支持主键？只按行号比对的话，一旦有人在中间插了一行，**后面所有行都会被标成差异**。按订单号、学号、工号这类唯一编号配对，行顺序变化就不会产生噪音。

**主键重复或为空会直接报错**，而不是静默给出一份错误的比对结论——这个取舍很专业。

### excel_dedupe：返回重复明细，而不只是行数

```python
from skills.excel import excel_dedupe

result = excel_dedupe(
    excel_path='客户名单.xlsx',
    key_columns='手机号',
    keep='first',
)

print(result['total'], result['unique'], result['duplicate_count'])
for dup in result['duplicates']:
    print(dup['row'], '与', dup['kept_row'], '重复')
```

排查问题时你需要知道「第 5 行和第 2 行重复」，只给一个 `duplicate_count` 数字没法用。

### excel2csv：默认 utf-8-sig 解决中文乱码

```python
from skills.excel import excel2csv

result = excel2csv(
    excel_path='报表.xlsx',
    output_dir='./csv',
)
```

**默认编码是 `utf-8-sig`（带 BOM）**，这是中文用户最高频的坑：存成普通 UTF-8 后用 Excel 双击打开会乱码，加 BOM 就正常。

需要喂给 Linux 工具链时，可以显式传 `encoding='utf-8'`。

### excel2json：三种结构，按下游选

```python
from skills.excel import excel2json

# records（默认）：[{"姓名": "张三", "部门": "销售"}, ...]
# columns：{"姓名": ["张三", "李四"], "部门": ["销售", "市场"]}
# values：[["张三", "销售"], ["李四", "市场"]]
result = excel2json(excel_path='报表.xlsx', orient='records')
```

`excel2json` 输出给程序读，`excel2markdown` 输出给人看——两个方法不是重复，是各管一头。

### excel_column_stats：一份表格的体检报告

```python
from skills.excel import excel_column_stats

result = excel_column_stats(excel_path='报表.xlsx', top_n=5)
```

逐列输出填充率、推断类型、唯一值数量、数值分布和高频值。数据脏在哪一列，一眼就能看出来。

### 用法：按 Skill 分类导入

```python
from skills.excel import excel_diff, excel_dedupe, excel_column_stats, excel2json, excel2csv
```

> ⚠️ **注意**：这 6 个贡献者 Skill（`batch_rename_by_excel` + 上面 5 个）的实现代码位于仓库的 `contributors/` 目录，该目录**不随 pip 安装包一起发布**。从 PyPI 安装后调用它们会得到一条明确的 ImportError 提示，提示你克隆源码仓库使用或直接复制对应文件。这是贡献隔离模式的固有限制，不是 bug。

## 两个 PR 的协作过程

1.1.0 的功能全部来自社区贡献者。两个 PR 的协作里有几个值得记录的点。

### PR #184：CLI 的设计取舍

贡献者 Edwin.JH.Lee 提交了第一波 CLI 实现，提出**分波推进**：本波先跑通 7 个核心模块 42 个子命令，其余模块（video / web / word / ppt / wechat 共 20 个命令）后续分波补齐，注册表结构就绪，加入只是数据条目。

贡献者自建了一套测试基建，这是本 PR 最有价值的部分：

| 测试层 | 数量 | 说明 |
|---|---|---|
| `pytest tests/test_code/test_cli.py` | 37 passed | 内置 `po*` stub，**不装重型依赖也能跑 CI** |
| `.x-cmd/test.sh` real 模式 | 15/15 | 真转换 + 产物校验（txt2pdf→merge2pdf 页数、excel2markdown 表格、url2ip 真实 DNS） |
| `.x-cmd/test.sh` stub 模式 | 10/10 | 零依赖环境自动回退 |

`.x-cmd/Dockerfile` 提供了一个基于 `python:3.10-slim` 的干净环境镜像，apt 与 pip 均走 aliyun 镜像。贡献者在评论里记录了一个部署前置：PyMuPDF 需要 `libgl1 libglib2.0-0`，这是 slim 镜像的缺库问题，不是 PR 缺陷。

**评审意见里最值得看的一条**，是关于 PEP 562 懒加载的保留意见：

> 这个改造的收益是实打实的——`import office` 不再拖入 poexcel/popdf/povideo 这类重型依赖树，对 CLI 启动速度和安装体积都有帮助。但它有一个隐性代价：`__init__.py` 里不再有真实的 `from office.api import ...` 语句，IDE 的「跳转定义」「自动补全」会退化。

维护者的处理是：**先按贡献者的方案合入，但把代价记在账上**，并给出退路——后续可以把懒加载下沉到 `office/cli/` 内部，core 保持原样。

评审同时点名了三个做得好的细节：

1. 5 个 commit 拆得清楚（注册表 / 解析分发 / 输出 / 懒加载 / 文档），squash 后结构依然完整
2. 用内置 stub 预加载 `po*` 依赖，不装重型依赖也能跑 CI
3. `--json` 模式专门写了用例验证「库函数自己 print 时 stdout 仍干净」——**这个边界很多人会漏**

### PR #185：Excel 工具链的取舍

贡献者 my12yyds 贡献了 5 个 Excel 方法，并附 39 条单元测试。

过程中有一个**协作细节值得注意**：在 #183 合入时，维护者发现贡献者新增了 `skills/file/batch_rename_by_excel/` 目录，却没在父包 `skills/file/__init__.py` 里注册，导致 `from skills.file import batch_rename_by_excel` 会报 ImportError——这跟同目录其他 Skill 的导出方式不一致。维护者补了一个 `chore(skills)` 提交（`dd6f543`）完成注册，并在评论里说明「如果你希望这条注册由你自己提交，可以把 `dd6f543` revert 掉重新提」。

到了 #185，贡献者**主动在父包 `skills/excel/__init__.py` 注册了**，且严格只在末尾追加、不动既有行——正是 #183 漏掉的那一步，维护者在评论里专门点出了这一点。

另一个细节是 `DECLARATION.md`（贡献者声明文件）的措辞分寸：贡献者主动澄清「核心维护者仅指本贡献模块的维护责任人，不表示对上游的维护权与发布权」。维护者评价「这个措辞的分寸感很好」。

### 一个连续三次踩中的坑

#183 和 #185 的 6 个 Skill 都在 `__init__.py` 里用了 try/except 兜底，处理「`contributors/` 目录不随包发布」的情况。但写法有问题：

```python
except ImportError as _import_error:
    def xxx(*args, **kwargs):
        raise ImportError('...') from _import_error
```

Python 3 在 `except` 块结束后会**自动 `del` 掉 `as` 绑定的异常名**，闭包里引用的 `_import_error` 因而是未定义名字。真实 pip 安装环境（contributors 目录不存在）下调用这些 Skill，实际抛出的是：

```text
NameError: name '_import_error' is not defined
```

而不是作者预期的、带有明确指引的 ImportError 提示。

修复方式是把异常对象存到模块级变量：

```python
except ImportError as _import_error:
    _CONTRIBUTORS_IMPORT_ERROR = _import_error

    def xxx(*args, **kwargs):
        raise ImportError('...') from _CONTRIBUTORS_IMPORT_ERROR
```

回归测试新增在 `tests/test_code/test_contributors_skill_fallback.py`，显式 mock 掉 contributors 导入来触发兜底分支。**这个分支在源码仓库内永远不会自然触发**，所以常规测试抓不到——回退修复后新测试的 12 个 subtest 全部失败。

### 一条项目级的协作约定

从 #181 / #182 的处理能看出这个项目现在的规矩：**改动 `office/` 等核心目录的贡献，需要先开 issue 讨论，而不是直接提 PR。** 隔离式贡献（`contributors/` 目录 + `skills/` 包装）的可以直接提。

这条规矩的价值在于：**核心目录不被「顺手改一下」的 PR 反复扰动**，同时新贡献者也不用怕一不小心就改坏了主线。

## 升级方式

```bash
pip install python-office --upgrade
```

国内网络建议走镜像：

```bash
pip install -i https://mirrors.aliyun.com/pypi/simple python-office --upgrade
```

验证安装：

```bash
po --version
# po 1.1.0 (python-office)

po --help
# 7 个模块，42 个子命令
```

如果只想用 CLI 而不想装全部依赖，可以只装核心子库：

```bash
pip install python-office popdf poexcel poimage pofile wftools pomarkdown
```
